# 數字故障（glitch-digital）

> 數字訊號出了錯：像素被拉扯、資料塊錯位、壓縮偽影溢位、文字亂碼重排。畫面像一段正在崩潰又被修好的資料流。
> 參照（只學語法）：故障藝術（glitch art）、資料彎曲（databending）和 datamosh 作品、像素排序（pixel sorting）、解構主義平面設計、電子音樂的視覺。不照搬具體作品。

## 本質 / 不是什麼
- 本質：**數字媒介自己的錯誤**。故障來自數字訊號的物理規律：壓縮塊、編碼錯位、位元翻轉、記憶體讀錯；故障有結構、有節奏，落在拍上，錯誤本身在講內容（被入侵、被重寫、在升級）。
- 不是：模擬電視的掃描線和錄影帶噪聲（那是 `crt-vhs`）；也不是每一幀都在隨機抖動的「賽博」濾鏡。

## 辨識訊號：每支片子挑 2–3 個
| 訊號 | 長什麼樣 | 適合的主題 |
|---|---|---|
| 塊狀錯位 | 畫面被切成橫條或方塊，各自橫向錯開 | 衝擊、被入侵 |
| 像素排序 | 一片區域的像素按亮度拉成長條 | 融化、流逝、藝術感 |
| 壓縮偽影 | 8×8 的馬賽克塊、顏色量化的色階 | 低質量、資料損壞 |
| datamosh | 上一鏡的運動「拖」著下一鏡的畫面走 | 轉場、記憶錯亂 |
| RGB 通道分離 | 三個通道各自錯開，硬邊，不是模糊的色差 | 衝擊、數字 |
| 亂碼重排文字 | 字元隨機跳變，最後定成正確的詞 | 解碼、揭示、標題 |
| 位元圖案 | 0 和 1、十六進位制、記憶體轉儲鋪滿背景 | 底層、程式碼、駭客 |
| 壞死像素 | 幾個固定的亮點或壞行 | 螢幕、不完美 |
| 資料彎曲色彩 | 不自然的高飽和色塊和反色 | 迷幻、音樂 |
| 解構版式 | 文字被切開、旋轉、疊印，網格被故意打破 | 叛逆、態度 |
| 載入與重建 | 畫面從低解析度逐級清晰，或逐行重建 | 修復、升級 |

規則：
- 每支挑 2–3 個，至少一個不在下面「最俗的版本」裡。
- 訊號從主題裡選，不按順序全上。
- 故障是事件，不是底紋：平時畫面是乾淨的，故障只在重拍、轉場、關鍵詞上出現，每次幾幀到半秒。

## 這個風格最俗的版本
- 畫面：黑底、洋紅和青的色差全程抖動、橫條隨機錯位、文字一直在亂碼、到處是「ERROR」和十六進位制。
- 聲音：不停的 bitcrush 噪聲和隨機的電子嗶聲。
- brief 的 style 一欄寫明這支片子翻掉了哪幾條，或者為什麼刻意保留（比如使用者要的就是經典版）。保留時，把力氣花在構圖、鏡頭、節奏或一個意外的記憶點上。

## 適配
- 用途：片頭、金句卡點、電子音樂的視覺、產品釋出裡的「重構 / 升級」段落、作品集的高潮。
- 內容：網路安全、AI、開發者工具、電子音樂、遊戲、潮流品牌、「打破常規」類主題。
- 不適合：需要信任感、溫暖感的主題；文字需要長時間閱讀的段落（故障會幹擾閱讀）。

## 技術路線
內容先用 Canvas 2D 畫好（乾淨的版本），再用 WebGL 後期做故障：塊狀錯位按 `floor(uv.y * rows)` 取一個隨機偏移；RGB 分離分別對三個通道取樣；像素排序在 CPU 上對選中的區域按亮度排序（區域小一點，否則慢）；壓縮偽影用 8×8 塊的平均色加量化。所有隨機都用 `hash(塊序號, floor(t * fps))`，故障強度由 timeline 裡的事件驅動，不要每幀隨機開關。

## 材質與渲染
- 塊狀錯位：橫條高度不等（4–60px），偏移量隨強度變化，偶爾一條整個換成上一幀或下一鏡的內容。
- RGB 分離：硬邊、整像素偏移（2–12px），不要模糊。
- 像素排序：選亮度在某個區間內的像素，按列或按行排序，拉出長條。
- 亂碼：字元從一個字元集（A–Z、0–9、符號、方塊字元）裡跳，跳的頻率逐漸降低，最後逐字定成正確的詞。
- 重建：畫面先是 16×9 的馬賽克，按 2 倍逐級清晰，或者從上到下逐行「解碼」出來。

## 配色
下面的色值是示例，看思路，不要原樣照抄。
- 黑白加一個錯誤色：黑 `#0A0A0A` / 白 `#F2F2F2` / 錯誤紅 `#FF2A2A`
- 資料彩：近黑 `#0B0C10` / 熒光綠 `#39FF14` / 品紅 `#FF00A8` / 電光藍 `#00B3FF`
- 淺色解構：紙白 `#EDEDE8` / 墨 `#111` / 熒光橙 `#FF6A00`
- 推導：乾淨狀態下畫面用品牌或主題的配色；故障時才出現「錯誤色」（通道分離出來的原色、反色、高飽和）。洋紅加青的色差是最常見的那組，單一錯誤色或者淺底黑字的故障也很有力。

## 字型
等寬字型做資料和亂碼（JetBrains Mono、IBM Plex Mono、Space Mono）；標題用粗的怪誕體或窄體（Archivo Black、Space Grotesk、Anton），可以被切開、錯位、疊印。

## 運動
- 故障是瞬時的：2–8 幀的強故障，配合重拍；之後迅速恢復乾淨。
- 恢復乾淨也是一種動作：錯位的塊用 `snap` 歸位，通道用很快的彈簧 `{4, 0.9}` 合攏。
- 亂碼定字從左到右逐個落定，每個字 30–60 毫秒。
- 偶爾用一次「凍結 + 卡幀」：畫面停在一幀上重複 3–4 次再繼續。

## 畫面怎麼活
- 平時以乾淨為主：只留一兩個壞死像素、一條極細的錯位線偶爾閃一下。
- 背景的位元圖案或十六進位制緩慢滾動，亮度很低。
- 大的故障留給重拍，平時動得越少，故障越有衝擊力。

## 鏡頭語法
| 鏡頭運動 | 表達什麼 | 適合哪類內容 |
|---|---|---|
| 硬切加兩幀故障 | 衝擊、切換 | 卡點 |
| 推近到馬賽克塊，塊裡是下一鏡 | 進入資料內部 | 轉場 |
| 畫面「卡住」後跳到下一鏡 | 中斷、意外 | 反轉 |
| datamosh 拖拽轉場 | 記憶、混亂 | 段落切換 |
| 逐級清晰的拉出 | 修復、揭曉 | 落版 |

## 聲音調色盤
`glitch`、`blip`、短的 `noise` 爆裂，配合畫面故障的幀；音樂用 bus 的 `crush`（4–8 bit）在故障時突然加重、平時乾淨；`kick` 和 `snare` 可以加 drive。第 1 檔合成很合適。

律動與和聲（舉例，不止這些）：IDM 的碎拍、breakcore、或者乾淨的四踩被故障打斷（「卡帶」式的重複切片：同一小段音訊重複 3–4 次）；音簇、全音階、Phrygian；也可以用整段安靜的環境音，只在故障時出現刺耳的數字噪聲。聲音的故障和畫面的故障必須同幀。

## 原生手法
- 亂碼重排定成標題：適合片頭和落版（「解碼」）。
- 畫面崩成馬賽克，從馬賽克里重建出下一鏡：適合「升級」「重構」。
- datamosh：上一鏡的運動拖著下一鏡的像素走：適合轉場和記憶錯亂。
- 像素排序把畫面「融化」成流動的長條：適合流逝、溶解。
- 全程色差加橫條亂抖：經典，最俗的那一種。

## 變化空間
- 結構：一個系統被入侵 → 崩潰 → 修復；一張圖片被一層層壓縮到面目全非再復原；一句話被亂碼吞掉又一個字一個字救回來。
- 開場：乾淨的畫面突然卡住兩幀；黑屏上一行亂碼定成第一個詞。
- 結尾：所有故障收攏，畫面變得異常乾淨，logo 定格；最後一幀再閃一次故障。

## 坑
- 故障全程不停，眼睛很累、內容也看不清：故障是事件，平時要乾淨。
- 每幀隨機導致編碼後糊成一片、檔案巨大：隨機按幀號固定種子，故障區域有結構。
- RGB 分離做成了模糊的色差：數字故障是硬邊、整像素的。
- 光敏性：大面積高頻閃爍（每秒超過 3 次的全屏亮暗交替）可能引起不適，避免連續全屏閃白。
- 文字在故障裡讀不清：關鍵文字故障後要停留足夠長的乾淨時間。
