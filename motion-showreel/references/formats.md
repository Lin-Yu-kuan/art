# 用途：拍什麼、按什麼結構講

這份檔案只講**用途**：要傳達什麼、按什麼結構講、需要哪些素材、有哪些坑。畫面長什麼樣、怎麼動、配什麼聲音屬於**風格**，見 `styles/INDEX.md`。同一個用途可以配不同風格，比如 Logo 演繹既可以做成瑞士編輯風，也可以做成像素 CRT。

先找到對應的那一類，**只讀那一節**。結構只是起點，具體內容要從使用者的主題裡來。

| 用途 | 一句話 | 典型時長 / 畫幅 | 常配風格（只是常見搭配，不是限制） |
|---|---|---|---|
| A 動效作品集 | 展示動效功力，手法密集切換 | 12–20 秒 · 16:9 / 1:1 | swiss-editorial、kinetic-brutalist、particle-field、glitch-digital、comic-pop、mixed-media-era |
| B 產品宣傳短片 | 用真實的介面和賣點講清一個產品 | 15–30 秒 · 16:9 / 9:16 | minimal-ui、dark-keynote、glass-material、isometric-infographic、flat-vector、soft-organic |
| C UI 動效演示 | 一個元素連續變成一串介面狀態 | 10–16 秒 · 1:1 | minimal-ui |
| D 動態排版 / 金句卡點 | 字就是畫面，跟著節拍走 | 8–30 秒 · 9:16 / 16:9 | kinetic-brutalist、swiss-editorial、editorial-collage、risograph-print、comic-pop、glitch-digital |
| E Logo 演繹 / 片頭 | 一個想法，最後落成 logo | 4–8 秒 · 16:9 | 任意，常見 liquid-shader、particle-field、glass-material、cinematic-title、guochao |
| F 循環動圖 | 沒有開頭和結尾，可以無限播放 | 4–12 秒 · 1:1 / 9:16 | generative-geometry、liquid-shader、pixel-game |
| G 資料爆點 | 一個數字或一組對比的衝擊力 | 6–15 秒 · 9:16 / 16:9 | data-motion、swiss-editorial、dark-keynote |
| H 綠幕人物 + 程式碼場景 | 使用者提供人物素材，場景和特效用程式碼做 | 10–20 秒 · 9:16 | 任意，常見 editorial-collage、kinetic-brutalist、comic-pop |
| I 年代回顧 | 按時間講一段演進史，每個階段換一種媒介 | 45 秒–2 分鐘 · 16:9 | mixed-media-era、cinematic-title、painterly |
| J 口播講解 / 分章長片 | 按使用者原稿或錄音組織圖形講述 | 按確認時長，最長 20 分鐘 · 16:9 / 9:16 | 按主題選擇，可沿用全部風格 |

## A 動效作品集

刷屏最多的一類，原始提示詞通常只有一句「做一條 15 秒的動效影片，像簡歷裡的作品集，全力以赴」。上限很高，但結果不可控。這一類的做法是把「全力以赴」翻譯成具體的結構。

- **結構**（8 小節）：Hook（第一拍就有強烈的圖形動作）→ 2–3 段不同手法（排版、介面、幾何或粒子），每段 2 小節 → 加速 → 吸氣 → 記憶點 → 落版（名字或一句話），或者無縫回到開頭。
- **要點**：每段換一種手法，但配色、字型、運動性格要跟著所選風格貫穿全片，否則就成了模板合集。段與段之間的轉場要從內容裡長出來（craft.md 第 5 節）。
- **坑**：手法越多越容易散；每段只有約 2 秒，文字只能放 1–3 個詞；最後一定要有落版。

## B 產品宣傳短片

- **素材先行**：產品截圖、UI、logo、真實的功能名和賣點。使用者給的是網址或程式碼倉庫時，可以用 Playwright 擷取真實頁面（2× DPR），記下元素座標，讓鏡頭推到真實的按鈕上。**不編功能、資料、客戶和評價**，缺了就問或者留空。
- **結構**（16 小節，約 30 秒）：Hook（問題或反差）→ 產品亮相 → 3 個賣點（每個都配介面鏡頭、一句話、一個證據動作，比如數字跳動或流程走一遍）→ 彙總 → 落版（logo + slogan + 網址或日期）。15 秒版本只保留一個賣點。
- **技術**：截圖做成漂浮的螢幕，用遊標點選驅動介面狀態變化。多場景長片可以用 Remotion，但只在使用者要求或已經在用時才用；預設單個 HTML。
- **坑**：截圖推近後發糊；文字太多；品牌色被改。

## C UI 動效演示

參照公開的「介面變形」提示詞模板：全片只有一個元素，從頭到尾不切鏡頭。

- **結構**：8–12 個介面狀態排在節拍網格上，例如：按鈕 → 載入 → 對勾 → 播放器 → 進度條 → 滑塊 → 開關 → 標籤頁 → 圖表 → 命令面板 → 通知 → 回到按鈕。
- **技術**：同一個容器改尺寸、圓角、顏色（recipes.md 第 3 節）；遊標真的在拖（第 4 節）；指示條的前沿和後沿分開（第 2 節）。容器裡切換的內容要有自己的進場和出場。
- **坑**：被縮放的文字加了 `will-change` 會變糊；新舊文字疊在一起；循環接縫處遊標的位置或速度對不上。

## D 動態排版 / 金句卡點

- **結構**：文案拆成「一拍一個詞」或「一小節一句」，重點詞放在重拍上。整句出完後要停留到讀得完（craft.md 第 7 節）。
- **技術**：Canvas 或 DOM；逐字遮罩進場（recipes.md 第 1 節）。豎屏要把字排在安全區內。
- **坑**：詞太多、停留太短；中文字型沒做子集，渲染時出現方塊。

## E Logo 演繹 / 片頭

- **結構**（4–8 秒）：預備（暗示 logo 的元素）→ 爆發 → 成形 → 定格（logo + 品牌名，停留 ≥ 1.5 秒）。
- **素材**：**必須用真實的 logo 檔案**，SVG 最好，可以拆路徑做描邊或分塊組裝。拿不到就停下來問，不要用色塊冒充。
- **坑**：logo 的比例或顏色走樣；定格太短。

## F 循環動圖

- **結構**：一次完整的呼吸（聚 → 散 → 聚），最後一幀等於第一幀。
- **技術**：所有運動都寫成 `θ = TAU * t / DUR` 的整數倍頻率函式，噪聲在圓上取樣（recipes.md 第 11 節）。不要用逐幀累積的模擬。
- **驗收**：`inspect.mjs qa … --loop`（或 `LOOP=1 sh build.sh`），接縫那一步（最後一幀 → 第一幀）要和普通幀間的一步一樣平滑。聲音可以沒有；有的話，聲音也要能循環。

## G 資料爆點

- **結構**：鋪墊（問題或對比的一方）→ 數字滾動（1.5–2.5 秒）→ 落定（撞擊或反色）→ 一句解釋（停留 ≥ 2.5 秒）→ 來源（小字）。
- **技術**：計數器（recipes.md 第 9 節），配等寬數字；對比用尺寸表達，柱子從 0 開始長。
- **坑**：**數字只能來自使用者或可靠來源**，不確定就標出來讓使用者核對。

## H 綠幕人物 + 程式碼場景

程式碼畫不好寫實人物和複雜動作，所以讓影片模型只負責人物，其餘全部用程式碼做。

1. 使用者用影片模型（Seedance、可靈、即夢、Grok 等）生成人物片段：**純綠背景**、全身入鏡、不出畫。這一步由使用者完成，本 Skill 不呼叫影片模型。
2. 摳像：`ffmpeg -i dancer.mp4 -vf "chromakey=0x19FF0A:0.16:0.08,despill=type=green,format=yuva444p10le" -c:v prores_ks -profile:v 4444 dancer_alpha.mov`。顏色值從抽幀裡取，先摳一幀檢查邊緣。
3. 背景、大字、貼紙、分屏用程式碼渲成一層影片，按節拍變化。
4. 合成：`ffmpeg -i bg.mp4 -i dancer_alpha.mov -filter_complex "[0][1]overlay=(W-w)/2:H-h" …`。人物前面需要元素時，把人物匯出成圖片序列，在頁面裡按 t 選幀繪製。
5. 交付時寫清哪些畫面來自影片模型、哪些來自程式碼。

## I 年代回顧

參照公開傳播的程式碼版「電子遊戲發展史」：2 分鐘、多種媒介混搭、合成配樂，畫面跟著音樂剪。

- **結構**：開場（一個能貫穿全片的元素，比如一個像素點、一個光點、一個詞）→ 4–7 個階段，每段 8–20 秒，每段用那個階段的媒介來畫 → 高潮（所有階段匯合）→ 結尾（呼應開場）。
- **要點**：一根貫穿全片的線（同一個主角、同一種轉場、一首配器逐段升級的配樂）。沒有這根線，就成了風格拼盤。構圖骨架每段對齊，貫穿元素的動作按全片時間走，轉場借下一個媒介自己的出現方式，可以一路加速。風格規則見 `styles/mixed-media-era.md`。
- **製作**：超過 60 秒時先做低清小樣（`--size 960x540`）確認整體節奏，再按段落分別精修；渲染慢的段落（3D、著色器）單獨用 `--start --duration` 測試。
- **坑**：**史實必須準確**：年份、名稱、首創者都要核實，不確定的就不寫，列給使用者確認。

## J 口播講解 / 分章長片

- TTS 原稿必須由使用者提供；也可用使用者錄音，或製作沒有口播的分章長片。此用途不負責把文章代寫成口播稿。
- 有口播時先準備真實音訊和句段時間戳，用語義、停頓和重點組織畫面，再配 BGM 與音效；無口播時仍保留音樂節拍驅動。詳見 `narration.md`。
- 長片可以按章節改變構圖和鏡頭密度，保留共同的字型、色彩和圖形含義。不要把短片每拍換畫面的密度強行拉滿整片。
- 最長 1200 秒；與使用者指定時長衝突先確認。超過 2 分鐘按 `long-form.md` 分章構建、快取和審片，保留舊短片全部技術與風格能力。
