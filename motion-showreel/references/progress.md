# 按需展示製作進度

需求問答時留意使用者是否說「想看製作過程」「邊做邊看」「即時看進度」「每個階段給我看看」。意思明確就啟用，不再重複詢問；未表達時保持預設的最終工作區預覽，不額外增加一道必答題。在需求摘要和 brief 中記錄使用者原話、是否啟用、進度頁連結。使用者中途提出也可開啟，已有成果可直接釋出。

這是同一個製作流程的展示入口。原來的需求確認、風格確認、真實口播時間軸、逐鏡自查、最終匯出確認和成片驗收照常進行，不要求使用者在每一個進度更新後回覆。不得為了展示進度降低畫質、簡化鏡頭、改稿、使用估算口播，或額外呼叫付費 TTS。更新已有成果即可。

## 儘早開啟穩定入口

使用者提出後，在約定的專案目錄上啟動：

```sh
node <skill>/scripts/editor.mjs <project> --progress
```

主動開啟輸出的本機網址。進度與剪輯共用一個工作區，頂欄「製作進度」開啟階段抽屜，只保留一套頂欄與畫面控制元件。可以先是空目錄，還沒有 `index.html`、音訊或製作規格；此時顯示需求階段與說明，不生成佔位樣片，不擅自決定時長和幀率。確認需求後正常 scaffold 同一個目錄。保持服務執行，這個連結始終作為專案入口。可播放版本準備好後自動開啟該版本的完整工作區，瀏覽器地址會變為版本地址，使用者無需手動換連結。

## 製作時更新

階段 ID：`brief` 需求與腳本、`style` 風格與畫面、`narration` 口播樣例、`scenes` 鏡頭製作、`audio` 配樂與音效、`review` 最終預覽。狀態可用 `pending`、`running`、`ready`、`failed`、`skipped`、`waiting`（等待使用者反饋）；無口播/無聲等階段明確標為不需要。

```sh
node <skill>/scripts/progress.mjs <project> --stage brief --status running --message "正在確認內容、畫幅與聲音方案"
node <skill>/scripts/progress.mjs <project> --stage scenes --status running --done 2 --total 8 --message "兩個鏡頭已完成自查，繼續製作第三個"
node <skill>/scripts/progress.mjs <project> --stage narration --status skipped --message "本片不需要口播"
```

沒有填寫新計數時保留已有完成數。釋出部分鏡頭預設仍為製作中；整個階段完成時才設定 `--status ready`。數量只填實際完成數，不用計時器編造百分比。一個階段的子任務完成時可更新計數，不按每次敲程式碼重新整理。開始新階段、得到可預覽成果、遇到需使用者處理的問題時更新說明。進行中會顯示旋轉圖示，頂欄保留當前階段和完成數；動畫只表達任務未結束，不模擬完成比例。等待確認時用 `waiting`，不要保持旋轉造成仍在運算的錯覺。

### 收到確認，先解除等待

進度頁只讀取製作端釋出的狀態，不能自行讀取對話。**使用者確認後的第一個操作必須同步狀態**，然後再查資料、下載字型、搭建專案或製作鏡頭；不要等下一份成果完成才更新。需求確認後腳本通常還沒寫完，因此先恢復當前階段的製作狀態，不把確認冒充腳本完成：

```sh
node <skill>/scripts/progress.mjs <project> --stage brief --confirm --message "需求已確認，正在整理腳本與分鏡"
```

當前階段的成果確已完成、且要開始下一階段時，可一次寫入兩項狀態：

```sh
node <skill>/scripts/progress.mjs <project> --stage style --confirm --next scenes --message "風格已確認，正在製作第一鏡"
```

`--confirm` 只依據真實使用者反饋呼叫，重複執行不會讓進度倒退。確認過的階段再次請求反饋時，用 `--status waiting --reopen` 明確開啟新一輪，例如修改後的風格圖或最終預覽；不能用舊的待確認訊息覆蓋已經收到的確認。補發較早階段的已完成成果不會搶走當前階段。`--confirm` 僅同步製作狀態，不生成 MP4，也不免除後續確認與驗收。

等待期間檢測到專案原始檔變化，頁面會提示狀態可能未同步；製作中或等待超過三分鐘未更新，也會顯示未上報提示。這些提示不會自動批准、推進階段或釋出檔案。看到提示時核對對話與實際工作，補報真實狀態，不靠定時重新整理時間戳掩蓋漏報。

風格幀和音色短樣沿用原流程產物，自查後釋出：

```sh
node <skill>/scripts/progress.mjs <project> --stage brief --preview brief.md --name "需求與分鏡" --status ready
node <skill>/scripts/progress.mjs <project> --stage style --preview qa/directions.png --name "風格方向" --status waiting --message "三個風格方向，等待你選擇"
node <skill>/scripts/progress.mjs <project> --stage narration --preview audio/voice-sample.wav --message "使用你提供的原稿生成的音色短樣"
```

只接受專案內的圖片、音訊或 `.md/.txt/.json` 檔案；複製為獨立成果，原始檔繼續修改不會破壞正在檢視的樣例。需求、風格、聲音等階段下面保留相應成果按鈕。鏡頭製作階段只展示狀態、完成數量和進度條，不在右上角列出所有鏡頭；鏡頭與完整版本在畫面預覽工具欄的選擇器裡切換。階段已就緒不等於使用者已批准。需求/腳本階段顯示真實文字進展；有畫面或音訊後才展示對應成果。

## 鏡頭做完一個，就釋出一個

這一步是製作方式，不是事後補進度。開做第一鏡前確定總數、更新 `0/N running`；第一鏡完成並自查後立即釋出，讓使用者可以先看，再繼續第二鏡。長片優先複用原來的章節/鏡頭模組和素材快取，將已完成的鏡頭打包為獨立可播放目錄；該目錄有自己的 `index.html`、`DUR` 與實際依賴，渲染使用同一個鏡頭實現，不另做低質代理或近似動畫。整片尚未存在也能釋出第一鏡，不檢查尚未製作的其他鏡頭。

```sh
node <skill>/scripts/progress.mjs <project> --stage scenes --status running --done 0 --total 8 --message "正在做第一鏡"
node <skill>/scripts/progress.mjs <project> --stage scenes --shot s01 --total 8 --name "鏡頭1：種子落下" --publish shots/s01 --size 1920x1080 --fps 30 --message "第一鏡已自查並可播放，繼續製作第二鏡"
node <skill>/scripts/progress.mjs <project> --stage scenes --shot s02 --total 8 --name "鏡頭2：葉片展開" --publish shots/s02 --size 1920x1080 --fps 30
```

`--shot` 僅用於 scenes，必須有穩定 ID 與 `--total`。通過檢查才加入成果列表並自動更新完成數；同 ID 修訂替換原成果，不重複計數。失敗保留舊成果和原數量。獨立預覽只需複製和檢查該鏡目錄，不要求先製作整片，不編碼 MP4。使用者可以在畫面區的鏡頭選擇器切換任意已完成鏡頭或完整預覽；主動回看會暫停自動切換，避免立即被拉回最新版。最終合片繼續使用原時間軸、聲音和驗收流程，不自動將這些預覽拼成成片。

舊的單頁面專案也可作為完整階段釋出，但不能為了這一種入口，等整批鏡頭寫完才展示。相同原則用於長片：先給第一鏡/第一章，而不是整片做完再更新進度。

## 釋出可播放的階段版本

完成一個可獨立檢查的鏡頭或階段，**先按原流程自查**，再發布可播放專案。規格用使用者已經確認的值：

```sh
node <skill>/scripts/progress.mjs <project> --stage scenes --publish . --size 1920x1080 --fps 30 --message "當前已完成的鏡頭；尚未加入最終配樂"
```

`--publish .` 把當前專案複製成獨立版本，帶上素材、字型、音訊與執行依賴，在副本中跑原有確定性檢查後釋出；不會編碼 MP4。可以釋出 `<project>` 內的另一個完整專案目錄（需 `index.html`），例如章節或獨立動作預演。未做好的部分要在說明中寫清，不用 starter 冒充已完成鏡頭。尚無混音時可無聲預演；不把預演聲稱為口播對齊完成。

進度頁每秒讀取一次狀態。新版本通過釋出檢查後在完整工作區開啟，載入原場景、字型和真實試聽；釋出失敗保留上一版。正在寫的程式碼不直接熱過載進使用者頁面。使用者可以關閉「自動切換階段版本」，自行選擇切換時機。階段版只讀，保留播放、拖動和逐幀檢查，不開放音軌編輯與匯出。

音訊完成後用同樣方式釋出 `--stage audio`，讓使用者檢視畫面與當前實際混音。不要為進度頁另外製作近似配樂、佔位口播或降低畫面複雜度。每次複製與檢查仍有少量開銷，按有意義的成果釋出，不按擊鍵釋出；版本和狀態儲存在 `.showreel-progress/`，不改原始製作檔案。依賴規模較大時優先按章節釋出，保留現有章節快取。

## 最終預覽與匯出

完成正常的畫面與音訊自查後，釋出最終預覽：

```sh
node <skill>/scripts/progress.mjs <project> --stage review --publish . --size 1920x1080 --fps 30 --final --status waiting --message "最終畫面與混音已準備好，請預覽後確認匯出"
```

釋出最終版時，若 brief 含 `--subframes`、`--shutter`、`--dpr`、`--grain`、`--crf` 或 `--workers`，將同一組引數附在這條命令上；原始混音需顯式指定時傳 `--audio audio/final.wav`。不能因進度頁提前開啟，就沿用當時尚未確認的預設匯出質量。

只有 `review --final` 開放獨立音軌編輯和匯出。進入最終版本時自動關閉版本切換，保護使用者的調音與正在進行的匯出；新版本準備好後，預覽工具欄出現「檢視新版本」，使用者手動切換。當前任務尚未結束或編輯未儲存時暫緩切換。使用者點選「匯出影片」即確認匯出，沿用 [`editor.md`](editor.md) 的原場景渲染、音訊和技術驗收。僅看過製作進度不代表確認最終匯出。

最終版在 `.showreel-progress/revisions/<版本>/project/` 中執行；編輯儲存、匯出檔案、驗收材料和 receipt 都位於這個版本內。交付時給實際輸出路徑和該版本的原始碼/編輯記錄，不誤指向根目錄的舊 `out/final.mp4`。如果使用者在對話中批准，匯出同一最終版本：有音軌編輯時仍從該版本的工作區匯出，保留 `.showreel-editor/session.json`；未改音軌時也可對同一版本按原構建流程匯出。不能把未預覽的工作檔案當作已批准版本。

長片的進度頁按章展示，註明章名和全片位置；當前工作區仍是單頁時間線。不要將一個章節用 `--final` 冒充全片；完成各章預覽並取得整片匯出確認後，仍按 `long-form.md` 的 `build-long.mjs` 合成全片，保留分章快取與跨章驗收。若使用者要獨立匯出某章，再明確作為單獨交付處理。

預覽不能代替原來的確定性檢查、音畫對齊自查、成片技術驗收和人工複核。即時播放可能掉幀，匯出中的子幀混合、DPR 超取樣和後期顆粒仍見 `editor.md` 的預覽限制。
