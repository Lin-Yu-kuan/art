# 驗收與審片

兩件事，分開做：

| | 技術檢查 | 審片 |
|---|---|---|
| 判斷什麼 | 檔案對不對：能否解碼、尺寸、幀率、時長、幀數、音軌、黑幀、響度、峰值、循環接縫 | 好不好看、好不好聽、有沒有達成 brief |
| 誰來判 | 程式（`inspect.mjs qa`，PASS / FAIL） | 人。Agent 先看圖寫出觀察，**使用者終審** |
| 結果 | 有任何 FAIL 都不能交付 | 記錄問題和修改，已知問題如實告訴使用者 |

**自己打的分不能代替驗收。**抽幀只驗證構圖，連續小樣用於驗證運動；有試聽能力時再核對聽感。審片記錄說明實際看過和聽過的範圍，不能把截圖、波形或自動計量當作完整觀看。

---

## 1. 技術檢查

```bash
node <skill>/scripts/inspect.mjs qa <slug>/out/final.mp4 --out <slug>/qa/final \
  --expect-size 1920x1080 --expect-fps 30 --expect-duration 16 \
  --audio required          # 有聲片；無聲片用 --audio none
  # 循環片再加 --loop（接縫那一步要和普通幀間的一步一樣平滑）
```

| 檢查 | FAIL 條件 |
|---|---|
| 檔案能解碼 | 讀不到影片流，或者幀數為 0 |
| 尺寸 / 幀率 / 時長 | 和 `--expect-*` 不一致（時長允許 ±1.5 幀） |
| 幀數 | 和時長 × 幀率相差超過 2 幀 |
| 音軌 | `required` 時沒有音軌，或者 `none` 時卻有音軌 |
| 黑幀 | 出現任何黑幀段 |
| 響度 / 真峰值（有音軌時） | 超出 −14 ± 1.5 LUFS，或真峰值 > −1 dBTP |
| 循環接縫（`--loop`） | 最後一幀 → 第一幀的 SSIM 比它兩側的普通幀間步（倒數第二 → 最後、第一 → 第二）低 0.03 以上，且低於 0.97。最後一幀本來就比第一幀早一幀，所以快速運動的循環首尾幀不會完全一樣，比較的是「這一步跳沒跳」 |

沒傳的規格項（尺寸、幀率、時長、音軌）會列成 `NOT CHECKED`，結尾也不會說「全部通過」。這時不算驗收，要按 brief 的規格重跑。`sh build.sh` 會用頂部的 `FPS / SIZE / AUDIO / LOOP` 和 `timeline.js` 的 `DUR` 自動帶齊。

引數寫錯（比如 `--audio requried`、`--expect-size 1920*1080`）會直接報錯退出，不會悄悄跳過那一項檢查。

另外：`render.mjs` 發現幀數不對、頁面報錯、編碼器退出時，會直接失敗，不留下任何輸出；`--determinism` 必須通過。`build.sh` 在出片之前自動跑一次（`DETERMINISM=0` 只在草稿時跳過）。

## 2. 審片

講解、演示和敘事片要檢查內容是否在畫面中發生：物件的前後狀態是否清楚、鏡頭是否承接、是否只是換標題卡與靜態板式。挑一段覆蓋狀態變化和接縫的連續小樣，帶聲音播放並拖動/逐幀看關鍵點。檢查物件身份、空間方向和動作速度，不用大面積背景運動掩蓋主體不動。Logo、動態排版和刻意靜止的風格按 brief 判斷，不強加持續運動。

有口播時先執行 `narration.mjs check`（用法見 `narration.md`），再逐句核對使用者原稿是否完整、語音是否有漏字/重複、畫面是否跟隨句段重點。檢查人聲期間 BGM 與音效是否避讓；自動響度通過不等於人聲清晰。TTS 稿件仍由使用者提供，發現錯字要請使用者修訂，不自行改寫後重合成。長片按 `long-form.md` 逐章提供材料，並複核每個章節接縫；全片總覽不能代替分章審查。

`qa` 同時會給出審片材料：`-sheet.png`（24 格抽幀）、`-phone.png`（資訊流尺寸）、凍結段、切點、音訊的波形圖和頻譜圖。凍結段落在 `timeline.js` 的 `HOLDS` 裡會標成「intended hold」；其餘的都要判斷是不是空拍，刻意的就補進 `HOLDS`，不是的就修。寫了 `DROPS` 時，音訊部分還會給出每個重拍前的呼吸凹陷。快速動作、轉場、記憶點處，再用 `inspect.mjs strip --at <秒>` 看連續幀。

還有兩份量出來的線索，同樣不判 PASS / FAIL，看完自己下結論：

- **按鏡頭的運動**（`qa` 和 `inspect.mjs motion` 都會列印；`timeline.js` 有 `SHOTS` 時按鏡頭分，沒有就按硬切分段）：每個鏡頭裡每一幀步有多少畫面在變（moving）、多少幀步完全不變（still）、有幾次突然的跳變（jumps）。重點看三種提示：「nothing moves」（不在 `HOLDS` 裡的長時間不動）、「sudden jumps」（整屏噪點隔幾幀重新生成一次，讀起來就是閃；或者某一幀穿幫）、「every other step is still」（步進動畫，或者鏡頭也被步進了）。另外單獨列出 **flash frames**：某一幀和前後兩幀都不一樣、前後兩幀卻一樣，多半是一幀閃白、一幀空畫面或一層東西漏畫，除非是刻意的單幀頻閃。一連串緊挨著的整屏大變化會單獨列成 **rapid whole-frame changes**：快速蒙太奇是刻意的；筆觸、噪點、紋理隔幾幀整屏重新生成一次，看起來就是閃。
- **文字框景**（`render.mjs --text-check`，`build.sh` 預設會跑，結果在 `qa/text.json` 和 `qa/text-t<秒>.png`）：字被畫面邊緣切掉（CUT；展示級大字出血記為 BLEED，多半是刻意的）、兩串不同的字疊在一起（OVERLAP）、豎屏字落進平台 UI 會蓋住的上下安全區（SAFE）、字小到手機上讀不出（TINY）。持續 ≥ 0.3 秒才報，每個時刻出一張標了框的圖。它看得到 Canvas 2D 和 DOM / SVG 的字，看不到 WebGL 紋理和圖片裡的字，這些幀要自己看。

文字框景檢查讀取原頁面，不會驗證子幀平均後的像素。使用運動模糊且有文案或鏡頭硬切時，匯出後用 `inspect.mjs strip --at <切換秒數>` 檢查成片的連續幀，留意只出現一幀的疊印。需要區分文案狀態和連續運動時間時，可按 `stack.md` 的可選取樣上下文接入；保留有意的交叉淡化。

逐項寫觀察，**不適用的寫「不適用」**：

| 項 | 看什麼 | 什麼時候不適用 |
|---|---|---|
| 開場 | 前 1 秒有沒有抓住人的東西 | — |
| 節奏與密度 | 變化密度是否符合用途和風格；有沒有無意的空拍；有沒有呼吸 | — |
| 運動質感 | 是否符合風格的運動規則（彈簧 / snap / 步進 / 週期）；快速運動是否卡頓 | — |
| 內容變化與鏡頭承接 | 關鍵論點有沒有由物件/關係變化呈現；是否逐句換頁；跨鏡主體、方向、速度是否意外重置；連續小樣是否實際看過 | 純排版、Logo 或靜止為設計意圖時按用途判斷 |
| 構圖與可讀 | 主體大小、留白；文字在手機尺寸下能否讀清、停留是否夠長；`--text-check` 標出的每一處 | — |
| 內容與數字口徑 | 畫面完美、內容錯的情況：數字、單位、名稱和使用者給的一致嗎？倍數的說法對嗎（「漲了 9 倍」和「漲到原來的 9 倍」不是一回事）？圖上的數能不能算出畫面說的結論？柱子從 0 開始嗎，縱軸截斷時寫明瞭嗎？示意資料標了「示意」嗎？展開、換鏡之後計數有沒有從 0 重來？ | 沒有事實、資料和圖表的片子 |
| 記憶點 | 有沒有一個清楚的記憶點，做得是否乾淨 | 用途本身不需要的（比如純循環背景） |
| 風格一致 | 所選風格（或改造 / 混搭 / 自定義規則）是否從頭守到尾；有沒有落入禁止清單；混搭時那根貫穿的線是否清楚 | — |
| 有沒有落成俗套 | 對照風格檔案「最俗的版本」：畫面和聲音是不是基本照著它來的？brief 裡挑的訊號真的出現在畫面上了嗎？換一個主題，這支片子的畫面還能原樣套上去嗎？能套上去，說明它沒有從主題出發 | 使用者明確要經典版 |
| 音畫關係 | 撞擊、切點、音效是否對齊；drop 前的留白 | **無聲作品** |
| 完成度 | 閃爍、穿幫、文字重疊、結尾 | — |

記錄到 `qa/review_log.md`：

```markdown
## 第 N 輪
技術檢查：全部 PASS（或列出 FAIL 項）
審片觀察：
- 開場：…  - 節奏與密度：…  - 音畫關係：不適用（無聲）
最嚴重的 3 個問題：
1. [4.2–5.0s] 卡片形變是勻速的，和「極簡介面」的彈簧規則不符 → 改用 springTo { freq: 2.4, damp: 0.75 }
2. …
重渲範圍：2.0–9.0s
仍未解決（交付時告訴使用者）：…
```

匯出前的修改先重新整理工作區、復看相關區間，讓使用者確認後再合成 MP4；不為每次審片先生成影片。已匯出的成片發現問題時，也先修正並回到工作區復看；確需離線片段時經使用者同意只重渲必要範圍（`render.mjs --start --duration --out out/seg.mp4`），當前版本確認後再出整片，並重新跑技術檢查。一般要兩三輪，但目標是解決問題，不是湊一個分數。同一類問題連著三輪都沒修掉、兩種修法都不管用，就別再在這一段上磨了，回到 brief 換做法（換技術、換鏡頭、換結構），或者如實告訴使用者。

### 獨立審片（宿主支援子 agent 時）

做片子的人自己看了三遍也看不出的問題，一個沒參與製作的人往往第一眼就看出來：動作重複了幾遍、兩個元素重疊成一個怪東西、字讀成了另一個詞。宿主能派子 agent 時，交付前派一個只看成片材料的審片 agent：

- **給它的**：`qa/` 裡的抽幀圖、手機尺寸圖、關鍵處的 `strip` 連續幀、`--text-check` 的標記圖、音訊的波形和頻譜圖，加上 brief 裡的「觀眾記住的一句話」和禁止清單。**不給**程式碼、製作過程和你自己的審片記錄，免得它跟著你的思路走。
- **讓它交回的**：按嚴重程度排的問題清單，每條帶時間碼、看到了什麼、它猜的原因；以及它最不確定的三處。
- **怎麼用**：它的結論和你自己的審片分開記進 `review_log.md`，修完再讓它看一次，區分「舊問題修好了」和「新發現的問題」。它說「缺一個記憶點、缺一個梗」，就把這條轉給使用者判斷；要往片子里加東西，先問使用者。
- 宿主沒有子 agent 時跳過這一步，審片表照常由你來寫。不管有沒有這一步，都不能代替使用者自己看片。

## 3. 常見問題和修法

| 症狀 | 原因 | 修法 |
|---|---|---|
| 連續靜態卡片、像幻燈片 | 把每句口播當一頁，只有文案替換、淡入和裝飾運動 | 重做語義分鏡，明確物件狀態變化與跨鏡承接；先看連續小樣，再調運動質感 |
| 快速運動卡頓、接縫突然停一下 | 步進作用到鏡頭、軌跡每句重啟、速度不連續，或運動取樣不足 | 保留風格所需步進但讓鏡頭連續；統一動作時間，修接縫速度，再按需要加拖影/子幀 |
| 整屏在閃（motion 報 sudden jumps 或 rapid whole-frame changes） | 筆觸、噪點、紋理每隔幾幀整屏換一次種子 | 筆觸和顆粒的位置固定，讓方向、亮度這類引數隨 t 連續變化；手繪抖動只給線稿和小區域；膠片顆粒交給 `--grain` |
| 某一幀一閃（flash frames） | 某一幀漏畫了一層、畫了空畫面，或者某個時間窗只有一幀寬 | `inspect.mjs frames <video> <秒>` 看那一幀；檢查那個時刻前後的 `seg()` 視窗和圖層順序 |
| 撞擊聲先到、畫面後到 | 轉場從拍點開始，新畫面過幾幀才露出來；鏡頭衝擊只加在新層上 | 用 `revealOn(hit, dur, reveal)` 倒推轉場起點；衝擊加在整個舞臺（recipes.md 第 14 節） |
| 簽名轉場被看成普通擦除 | 時長太短，緩入緩出的兩頭看不出變化 | 複雜轉場給 0.45–0.6 秒，`strip --at` 確認中段讀得出 |
| 年代 / 媒介切換時主角姿勢跳一下 | 每段按段內時間重演動作 | 貫穿元素的動作按全片時間算（mixed-media-era.md） |
| 字發糊 | `will-change`；畫布沒按 DPR 設定；素材解析度低 | 去掉 will-change；`setupCanvas`；2× 素材；`--dpr 2` |
| 新舊文字疊在一起 | 容器裡的內容沒有單獨的進場和出場 | 舊內容先模糊淡出，新內容延後進場 |
| 大字看起來像亂碼、重影 | 字壓在同色的繁忙內容（體塊側面、粒子、陣列）上，不是字型或程式碼問題 | 先單獨關掉內容層渲一幀確認字本身沒問題；再給字劃禁入區，用取景中心或主體輪廓讓開（stack.md 第 4 節） |
| 前幾幀字型不對 | READY 設得太早 | `await loadFonts()` 之後再設定 READY |
| 文字突然消失 | 動畫引數算出了 NaN（比如空的或無限長的時間窗） | 用 `seg()`（不會產生 NaN）；給離場時間用 `null` 而不是 `Infinity` |
| WebGL 層全黑 | 著色器編譯失敗；沒開 `preserveDrawingBuffer` | 編譯失敗就拋錯；先渲一幀確認 |
| 重渲的一段對不上 | 狀態、隨機數、計時器 | 用 `--determinism` 定位 |
| 看起來很「AI」 | 深色 + 居中大字 + 漸變 + 發光 + 同時淡入 | 回到風格檔案（`styles/<slug>.md`）的規則和 brief 的禁止清單 |
| 太鬧、太累 | 沒有層次，沒有呼吸 | 減少微變化；在 drop 前留白 |
| 結尾突然斷掉 | 沒有落版；音樂在小節中間被截斷 | 落版停 ≥ 1.5 秒，或者做無縫循環；時長取整小節 |
| 聲音轟、發悶 | 低頻太多 | 見 sound.md 第 9 節 |

## 4. 交付清單

- [ ] 需求與風格確認已記錄，或使用者明確免除；必填資訊明確，確認時長不超過 1200 秒
- [ ] 預設已開啟工作區並記錄當前版本的預覽與匯出確認；長片逐章預覽，或使用者明確要求跳過預覽
- [ ] TTS 使用使用者原稿；有口播時真實音訊、句段時間戳和畫面一致，時長衝突已確認
- [ ] BGM、音效來源分別與需求一致，人聲期間音樂與音效收斂；不把計量通過當作聽感通過
- [ ] 長片章節清單、區域性原始碼和音訊可重建，各章檢查和接縫複核有記錄
- [ ] 敘事/講解片看過代表性連續小樣；內容有可理解的狀態變化，鏡頭承接自然，沒有用文字換頁或裝飾運動替代講解

- [ ] `inspect.mjs qa` 技術檢查全部 PASS，沒有 NOT CHECKED（引數和 brief 的規格一致；用 `sh build.sh` 最省事）
- [ ] `--determinism` 通過
- [ ] 事實、數字、名稱和使用者提供的一致；不確定的已單獨列出
- [ ] 文字在手機尺寸下可讀，沒有溢位或重疊（`qa/text.json` 裡每一條都看過，刻意的出血、微註釋在審片記錄裡寫明）
- [ ] 按鏡頭的運動和 flash frames 都看過：沒有不在 `HOLDS` 裡的空拍、沒有意外的閃幀
- [ ] 素材和字型的授權已列出
- [ ] `qa/review_log.md` 寫明瞭審片觀察、改了什麼、還剩什麼問題
- [ ] `brief.md`、`build.sh`、實際匯出的 MP4（`out/editor-<task-id>.mp4` 或 `out/final.mp4`）及 `out/poster.png` 都在專案目錄裡；編輯版附對應會話與任務記錄
- [ ] 交付說明裡請使用者自己看一遍成片（有聲片要開啟聲音）
