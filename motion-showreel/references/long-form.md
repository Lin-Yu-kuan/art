# 長片：章節、構建與審片

適用於超過 2 分鐘、最長 20 分鐘的影片。長片與短片一樣，預設先開啟剪輯工作區預覽，使用者確認後才渲染 MP4。短片仍使用單頁面，長片保留原來的章節構建、快取與驗收。

## 先規劃內容，再分章節

需求確認時明確總時長和是否允許浮動。口播實際時長與目標不符時先確認；超出 1200 秒也不能自動裁掉。TTS 必須使用使用者原稿；沒有口播時仍可用節拍驅動，保留現有全部風格和合成引擎。

brief 寫清章節目的、時長、銜接和貫穿元素。長片可以有多個重點，不必把短片的高速變化密度持續二十分鐘。字型、色彩、圖形含義保持一致，變化服務於講述。風格幀按主流程：已定風格出三幀，未定風格給三個方向；確定後可增加各章代表幀自檢。製作完成後另在工作區預覽，確認當前內容可以匯出。

按內容邊界拆章，通常每個構建單元 30–90 秒；這是控制渲染和音訊記憶體的建議，不是敘事規則。每章用獨立專案目錄與本地時間軸，從 `render(0)` 開始；總片時間 = 前面各章時長之和 + 章內時間。共享的設計 token、素材和構建依賴要列入各章的 `inputs`，避免快取漏掉外部變化。

構建單元不等於視覺段落。章內 `render(0)` 不意味著把主體、位置和運動重置；分片承接同一個動作時，使用共同的全片時間/軌跡或顯式銜接姿態。敘事段落切換允許有意的硬切，不能讓技術切片製造隨機停頓和空間跳變。口播句段也不要求逐句切鏡。

## 可重建的章節清單

在專案根寫 `chapters.json`，所有路徑相對此檔案。時長以秒計，章節按陣列順序拼接：

```json
{
  "version": 1,
  "duration": 180,
  "size": "1920x1080",
  "fps": 30,
  "chapters": [
    { "id": "intro", "project": "chapters/intro", "start": 0, "duration": 60, "audio": "chapters/intro/audio/final.wav" },
    { "id": "explain", "project": "chapters/explain", "start": 0, "duration": 60, "audio": "chapters/explain/audio/final.wav" },
    { "id": "end", "project": "chapters/end", "start": 0, "duration": 60, "audio": "chapters/end/audio/final.wav" }
  ],
  "render": { "workers": 3 }
}
```

`start` 是源頁面的章內取幀起點，不是最終影片中的開始時間。也可以讓多章引用同一頁面並用不同 `start`，但共用原始碼變更時，這些章會一起失效。章節時長應落在幀邊界，總和必須等於確認時長。

下面命令只在使用者確認預覽通過、可以合成整片後執行，不能用它先生成供使用者預覽的 MP4：

```bash
node <skill>/scripts/build-long.mjs <slug>/chapters.json
```

同一命令再次執行會複用通過校驗的章節快取；更改某章原始檔或渲染規格後，只重建失效章節。保留 `.showreel-cache/`，不要把正常中斷當作清空快取的理由。內部快取是技術產物，不代替原始碼、brief 和原始音訊。

- 每章保留獨立音軌：使用 `chapters[].audio`，缺音軌的章補等長靜音。章音軌時長衝突會報錯。
- 已有整片混音：改用頂層 `audio` 指向整片音訊，不再設定任何 `chapters[].audio`。它必須與確認的總時長匹配。
- 全片無聲：兩種音軌欄位都不設定；技術檢查要求沒有音軌。短片對應 `AUDIO=none`，不要把靜音 WAV 當作需要通過響度檢查的有聲成片。
- `--skip-qa` 只用於草稿，不能作為交付構建。最終必須用完整規格通過驗收。

## 音訊也按章製作

內建合成器和 Tone.js 都會分配整段取樣記憶體。不要為 20 分鐘整片建立多條 Float32 bus，再試圖靠增加記憶體完成。

每章寫自己的 `timeline.js`、`score.mjs` 或 `score.tone.js`，沿用原有音色、效果和卡點工具。先用 `audio.mjs build` 構建本章音樂/音效，再按 `narration.md` 與本章口播混音，得到本章 `audio/final.wav`，最後由章節構建器流式拼接。

使用者提供整段口播時，先獲得真實句段時間戳，再在自然停頓處分章；切分不得丟字或改變速度，所有章區間必須覆蓋確認過的完整內容。原始錄音保留。使用者原稿很長時，TTS 自帶按句段合成與快取；按章節選擇相應片段製作畫面。整片音軌可以保留在頂層，避免重複編碼人聲。

配樂在章邊界處預先設計延續、淡出或呼吸，不能把章節拼接當成任意截斷音樂的理由。連續音樂可先用流式 ffmpeg 拼接處理，最終統一做母帶；不要對本應安靜的章節各自強行拉到同一響度。人聲期間的避讓與最終混音見 `narration.md`。

## 分章驗收與全片驗收

合成前逐章開啟 `editor.mjs`（見 `editor.md`），提供章節順序和各工作區連結，複核章末與下一章開頭。多個章節共用同一頁面時，在該頁面的工作區用播放頭和循環選區定位；第一版不提供跨頁面連播。無聲章節同樣先預覽。預設等待使用者確認這一版整片內容後再開始構建，不要求每章重複確認匯出。

若工作區中改了聲音，構建輸入必須使用已確認的混音並通過對應的來源、時長和雜湊檢查。當前版本不自動把多章會話寫回 `chapters.json` 或 `audio/mix.json`；需在匯出專案中同步這些輸入和校驗記錄、保留原檔案後再構建，不能忽略編輯或關閉校驗來拼片。

構建前對各章跑 `render.mjs --determinism`；每章做靜幀、文字框景、運動與手機尺寸檢查，材料按 `qa/<chapter-id>/` 儲存。對每個切點前後看連續幀，檢查重複幀、漏幀、文字跳變和音訊接縫。

構建器對全片執行 `inspect.mjs qa`，檢查尺寸、幀率、總時長、幀數和最終音軌。全片抽幀只是目錄，不能代替逐章檢查。口播另跑 `narration.mjs check` 並逐句核對原稿、聲音和畫面；整片聽感仍交給使用者終審。交付章節清單、快取複用方式、重建命令、技術結果和已知問題，不宣稱僅憑抽幀已完整觀看或聽過全片。
