# brief.md 模板

`brief.md` 有兩個用途：這次製作嚴格按它來；以後換主題、換工具複用時，它就是一份完整的結構化提示詞。用 XML 標籤分塊，AI 模型能更準確地分清哪部分是要求、哪部分是素材、哪部分是約束。

填寫要求：首次需求確認之後才寫。已確認內容寫實，不留【】；必填項不使用未獲確認的預設值。推斷的受眾、平台和建議的技術規格註明依據。API 只記 provider、模型、音色和環境變數名，不記錄憑據。

```text
<role>
你是一位動態設計師兼創意程式設計師，用程式碼製作可以釋出的影片，保留短片的動效表現力，長片按內容節奏分章組織。
</role>

<inputs>
主題：……
觀眾記住的一句話 / 一個畫面：……
素材：……（檔案路徑；參考影片只學結構和手法；使用者的曲子寫明授權）
規格：…秒（≤1200，嚴格 / 允許浮動…秒）· 橫屏/豎屏 · …×… · …fps
製作過程預覽：啟用 / 未提出；使用者反饋依據……；進度頁連結……（啟用時按 progress.md 更新階段成果）
受眾 / 平台：……（使用者提供 / 根據……推斷）
內容依據：……（使用者具體描述 / 使用者口播稿 / 資料 / 調研來源；哪些素材由 AI 生成）
品牌：主色 #…，強調色 #…，字型 …（檔案在 fonts/）
BGM：AI 合成 / 使用者提供 / 關閉；引擎或檔案……；聲音方向……
音效：AI 合成 / 使用者提供 / 關閉；引擎或檔案……；動作與聲音對應……
口播：無 / TTS / 使用者錄音
（有口播時填寫）使用者原稿/錄音路徑：……；來源：使用者；原稿不改寫
（TTS 時填寫）provider / model / voice：……；配置環境變數名：……
（有口播時填寫）真實時長：……；句段時間軸：audio/narration.json；對齊來源：TTS 分段實測 / SRT / 轉錄工具
（有口播時填寫）混音：人聲優先；BGM 與音效各自的音量、避讓和密度……
</inputs>

<confirmations>
需求確認：使用者已確認的摘要、日期/訊息依據……
風格幀確認：使用者選中的方向、聲音方向與確認依據……（第 3 步確認後填寫）
最終預覽與匯出確認：工作區連結、當前版本、反饋與修改、使用者點選匯出或對話確認的依據……（第 6 步後填寫）
若使用者明確免除某次確認：記錄原話及免除範圍，不把「給我驚喜」當作免確認。
時長衝突及處理：無 / ……（衝突須使用者確認；不擅自裁切、變速或改稿）
</confirmations>

<direction>
Reel Read:
  format: …（用途，formats.md）
  benchmark: …（對標作品 · 學什麼 · 不學什麼；有參考影片時寫上 inspect grid / heat 量到的數：BPM、段長序列、每段運動面積）
  structure: …（三個候選結構 → 選中的那個和理由）
  style: …（styles/<slug>.md，寫明改造點；或混搭方案；或按 _template.md 寫的自定義規則）
  signals: …（從風格檔案「辨識訊號」裡挑的 2–3 個，為什麼跟這個主題有關；對照「最俗的版本」翻掉了哪幾條，或者為什麼保留）
  hook: …
  signature: …（記憶點：第幾秒，什麼手法）
  visual-language: …
  palette: 背景 #… / 主色 #… / 強調色 #…（只給主角用）
  type: 展示 … / 輔助 …
  motion: 彈簧 {freq …, damp …}（大字）/ {…}（UI）；緩動 …；是否步進
  camera: …（按風格和內容選擇；長片寫明章節間如何變化，口播段不為湊動作打斷講述）
  texture: …
  sound: …（無聲；或者：聲音對標 · 角色 · 律動 · 和聲 · 配器 · 曲線 · 動機 · 混音，能推出來的寫一個詞即可，見 sound.md 第 2 節；使用者曲子寫 BPM 和 drop）
整片只用一套視覺系統；同一個元素在每個鏡頭裡的樣子保持一致。
每個鏡頭有一個清楚的理解重點。展示文案精簡併停留到能讀完；不用把每句口播抄上屏。鏡頭可以跨多句，主體、空間與動作隨內容連續發展。
運動方式按所選風格（彈簧、snap、步進或週期運動）；轉場從畫面內容裡長出來，不用預設的淡入淡出。
禁止：……（針對這支片子寫具體的，比如：深色背景 + 居中大字 + 漸變；所有元素同時淡入；紫藍漸變和發光；角落裡的 HUD 標籤；勻速平移；Inter 做展示字型；有聲片也可以寫聲音的，比如 Am–F–C–G 循環、每個重拍都 impact + crash，見 sound.md 第 12 節）
</direction>

<structure>
（無口播）節拍網格：BPM …，共 … 小節（… 秒）；重拍 = 大變化，拍點 = 中變化，八分音符 = 微變化
| 小節.拍 | 段落 | 畫面（含原文文字） | 運動 | 鏡頭 | 聲音 | 轉場 |
|---|---|---|---|---|---|---|
| 1.1–2.4 | Hook | … | … | … | … | … |
| … | … | … | … | … | … | … |
（有口播時，用此表替代音樂節拍表；先寫預計區間，實際口播準備後回填真實區間）
| 鏡頭 / 關聯句段 ID | 要解釋的變化 | 物件起止狀態 | 繼承的物件與空間 | 事件 / 實測時間依據 | 鏡頭 / BGM / 音效 | 銜接方式 |
|---|---|---|---|---|---|---|
| … | … | … | … | … | … | … |
句段到鏡頭可以多對多；原稿保留在輸入檔案，分鏡不用重複全文。關鍵事件共用同一個時間變數；無實測詞時間時只能宣告句級同步，不能按字數均攤。
（超過 2 分鐘）章節表：各章專案路徑、全片起點、章內時長、銜接方式；章節時長之和等於確認時長；字型、品牌色、重複元素保持一致。
簽名時刻：…（小節.拍，以及具體怎麼做）
結尾：落版 … / 無縫循環
</structure>

<build>
1. 短片保留單個 HTML 檔案（或說明為什麼需要 Three.js / p5）；長片按 long-form.md 拆章節。內容層：…，質感層：…。
2. 頁面暴露 window.DUR / window.render(t) / window.READY；畫面只由 t 決定，隨機數帶固定種子，不用計時器，不用 CSS 動畫，幀和幀之間不儲存狀態。
3. 所有時間點寫在 timeline.js，頁面和 score.mjs 都從它 import；鏡頭表寫進 SHOTS；無口播時，要對拍的轉場用 revealOn(拍點, 時長, 揭開點) 倒推起點。有口播時先合成或分析真實音訊，再用句段時間戳定鏡頭，不用估時冒充對齊。
4. 渲染：render.mjs 逐幀截圖 → ffmpeg；引數：--fps … --size … [--subframes 4] [--dpr 2] [--grain …]。
5. BGM、音效分別取確認的來源，保留第 1 檔 score.mjs / 第 2 檔 score.tone.js。口播按 narration.md 準備；獨立軌用 narration.mjs mix，最終混音統一響度與峰值。有音效的動作落在動作那一幀；有口播時收斂配器與音效。三軌都關閉才寫「無聲」。長片音訊按章構建，不用整片 Float32 合成代替分段處理。
6. 每個鏡頭做完渲 3 張靜幀檢查；關鍵狀態變化和鏡頭接縫在工作區連續播放，檢查事件同步與動作承接。全部完成後跑 --determinism，主動開啟 editor.mjs 工作區供使用者預覽，不先出低清 MP4；使用者確認當前版本可以匯出後再出正片。
7. 使用者確認預覽通過後匯出並驗收：工作區匯出，或未改音軌時 sh build.sh（FPS / SIZE / AUDIO / LOOP 寫在 build.sh 頂部，時長取 timeline.js 的 DUR），等價於 inspect.mjs qa --expect-size … --expect-fps … --expect-duration … --audio required|none [--loop]；技術檢查全部 PASS，且沒有 NOT CHECKED。timeline.js 裡宣告 HOLDS（刻意的停留）和 DROPS（要留呼吸的重拍）。build.sh 還會出文字框景（qa/text.json）和按鏡頭的運動報告，這兩份是審片材料，每一條都要看過。
8. 混合音軌使用 AUDIO=file AUDIO_FILE=audio/final.wav sh build.sh；長片使用 build-long.mjs chapters.json，保持章節快取。有口播時檢查 narration.json 和實際音訊時長、逐句聲畫對應、原稿完整性；長片逐章檢查並複核接縫。
</build>

<gotchas>
……（這支片子特有的坑，比如：字型載入完再 READY；WebGL 先渲一幀確認生效；中文字型要子集化；循環片首尾幀完全一致；被縮放的文字不加 will-change）
</gotchas>

<start>
（按情況只保留下面一段）
【要確認 · 預設】需求已確認，才進入本 brief。已定風格：先出 hook、記憶點、結尾三張風格幀給我確認；未定風格：先給 3 個拉開差距的方向，各一張關鍵幀（render.mjs --directions）讓我選。連續動作是核心時同時附代表性運動小樣；TTS 給使用者原稿的分段方案和音色短樣。放在同一次風格確認裡，等我回復後再正式製作。
【不用確認 · 使用者明確免除風格幀確認】仍先出風格幀，自己看圖選一個，把選擇和理由寫進 brief，然後繼續。「你決定」只授權審美選擇，不自動免除確認。
之後：有口播先鎖定實測時間軸，再按鏡頭順序製作，每個鏡頭完成後自檢；畫面與混音準備好後預設開啟 editor.mjs 工作區（長片逐章預覽），等我確認當前版本可以匯出後才生成 MP4。工作區音訊編輯隨當前會話匯出；沒有音軌編輯時短片也可用 build.sh，長片按 long-form.md 用 build-long.mjs。技術檢查全部 PASS、沒有 NOT CHECKED 後，附上審片記錄交付。
</start>
```
