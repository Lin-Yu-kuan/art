# 極簡介面（minimal-ui）

> 乾淨的舞臺上，真實感的介面元素在變形、點選、拖拽，每一個變化都有彈簧手感。
> 參照（只學語法）：Dribbble 級別的介面動效、Apple / Linear / Vercel 的產品動效、公開的「介面變形」提示詞模板。不照搬具體品牌的介面和圖示。

## 本質 / 不是什麼
- 本質：**介面本身是主角**，在一個乾淨、安靜的舞臺上被真實地使用：一個元素連續變成下一個狀態，遊標真的在點、在拖，尺寸和圓角的變化都有彈簧手感。舞臺可以是淺色，也可以是品牌色或深色，只要安靜、不搶介面。
- 不是：賽博 HUD、深色加霓虹、擬物化；也不是把截圖平移一下的幻燈片。

## 辨識訊號：每支片子挑 2–3 個
| 訊號 | 長什麼樣 | 適合的主題 |
|---|---|---|
| 形變鏈 | 一個按鈕連續變成載入、對勾、卡片……不切鏡頭 | 功能串聯、流程 |
| 遊標操作 | 遊標移動、懸停、按下、拖拽，帶真實的加減速 | 互動、教程 |
| 浮起的卡片 | 白卡片帶柔和投影，從舞臺上浮起 | 產品亮相 |
| 前後沿拉伸 | 指示條移動時前沿快、後沿慢，被拉長 | 切換、導航 |
| 真實截圖裡的推近 | 鏡頭推到真實產品介面的某個按鈕上 | 產品宣傳 |
| 系統控制元件 | 開關、滑塊、分段控制元件、鍵盤快捷鍵提示 | 工具類產品 |
| 命令面板 / 搜尋 | 一個輸入框裡逐字出現查詢，結果列表彈出 | 效率工具、開發者 |
| 通知和 toast | 從角落滑入的提示，幾秒後收回 | 狀態、提醒 |
| 深淺色切換 | 同一個介面在亮色和暗色之間翻轉 | 主題、設定 |
| 手機或視窗外框 | 介面裝在一個極簡的裝置或視窗框裡 | 多端產品 |

規則：
- 每支挑 2–3 個，至少一個不在下面「最俗的版本」裡。
- 訊號從主題裡選，不按順序全上。
- 真實產品優先用真實截圖（stack.md 第 10 節），訊號挑的是怎麼展示它。

## 這個風格最俗的版本
- 畫面：淺灰底 + 正中一張白卡片 + 藍色強調色，按鈕 → 載入圈 → 對勾，結尾拉遠出 logo。
- 聲音：柔和的 click、pop 加一條幹淨的電子 pluck 旋律。
- brief 的 style 一欄寫明這支片子翻掉了哪幾條，或者為什麼刻意保留（比如使用者要的就是經典版）。保留時，把力氣花在構圖、鏡頭、節奏或一個意外的記憶點上。

## 適配
- 用途：UI 動效演示、產品宣傳短片、功能介紹、作品集裡的介面段。
- 內容：App、SaaS、開發者工具、AI 產品、設計系統。

## 技術路線
DOM / SVG（文字排版質量最好）或 Canvas。`render(t)` 裡直接寫樣式。快速形變多時用 `--subframes 4`；有細線和小字時用 `--dpr 2`。60fps 更順滑。

## 材質與渲染
- 圓角卡片（12–28px）、1.5–3px 細描邊或無描邊、柔和投影（只給浮起的那一層：`0 20px 60px rgba(0,0,0,.08)`）。
- 圖示線寬統一（1.75–2px），不用 emoji。
- 遊標：簡單的向量箭頭，按下時縮到 0.88 並出現擴散圓環。
- 可以有一層非常淡的顆粒（`--grain 2–3`）。

## 配色
下面的色值是示例，看思路，不要原樣照抄。
- 背景 `#EFEDE8` / 卡片 `#FFFFFF` / 墨 `#111111` / 灰 `#8A8780` / 強調 `#3B5BFF`
- 背景 `#F5F4F1` / 卡片 `#FFFFFF` / 墨 `#0F0F10` / 強調（品牌色）
- 規則：強調色只給當前被操作的那個元素，或者狀態成功的時刻。
- 推導：舞臺色（暖灰、冷灰、品牌色的極淺版、深色都可以）+ 卡片 + 墨 + 一個強調色。強調色優先用品牌色；藍色是最常見的那個。

## 字型
一款乾淨的介面字型加一款等寬字型：Geist、Instrument Sans、Manrope、Inter Tight；等寬用 Geist Mono 或 JetBrains Mono。中文用思源黑體 Medium / Bold。

## 運動
- 彈簧檔位：指示條、開關 `{3.6, 0.8}`；容器 `{2.4, 0.75}`；大標題 `{1.6, 0.95}`。最多帶一點回彈。
- 前沿和後沿分開（recipes.md 第 2 節）：移動中的條被拉長。
- 容器裡的內容換狀態時，舊內容先模糊淡出 0.1 秒，新內容延後 0.08 秒進場。
- 拖拽：按住時數值由遊標位置決定，鬆手後從當前位置彈回吸附值。

## 畫面怎麼活
- 遊標的待機：小幅漂移或停在按鈕上輕輕懸停；後臺的進度條、數值繼續走；一個狀態點（線上、錄製中）緩慢脈衝。
- 介面以外不加裝飾性動效，活的東西都應該是介面本來會有的狀態。

## 鏡頭語法
| 鏡頭運動 | 表達什麼 | 適合哪類內容 |
|---|---|---|
| 跟隨當前狀態縮放 | 聚焦當前操作 | 每一個介面狀態 |
| 輕微傾斜後回正 | 狀態切換的能量 | 形變的瞬間 |
| 拉遠到完整頁面 | 全貌、上下文 | 結尾、總結 |
| 推進一個按鈕 | 進入下一個功能 | 段落切換 |

## 聲音調色盤
介面音效在前：click、tick、pop、swipe、成功時的 `bell`。音樂退後（gain 0.3–0.4）：撥絃琶音（五聲音階）、輕底鼓、軟拍手。第 1 檔合成即可。

律動與和聲（舉例，不止這些）：直拍、輕 swing（俏皮的介面），或者 6/8；大調五聲、Lydian；一問一答（操作 → 介面回應）很合適；`mallet`（marimba、kalimba）可以替代 pluck。幹、短，不側鏈或很輕。

## 原生手法
- 形變鏈：按鈕 → 載入 → 對勾 → 卡片……一鏡到底。適合功能串聯。
- 拖過頭被拉長：適合滑塊、音量、進度。
- 開關的圓點變成下一個元件的指示條：適合流程銜接。

## 變化空間
- 結構：一個使用者完成一件事的完整路徑；一個元件的 10 種狀態；同一張卡片在亮色和暗色之間來回。
- 開場：一個按鈕被遊標點下的那一幀；空白畫面裡一根遊標進入。
- 結尾：所有狀態收回成最初的按鈕（循環）；拉遠露出完整產品介面和 logo。

## 坑
- 被縮放的元素加了 `will-change`，文字會糊。
- 新舊文字疊在一起。
- 投影太重、描邊太粗，會變廉價。
- 用 CSS 畫一個假介面冒充使用者的真實產品：真實產品要用真實截圖。
