# 像素立體場景（pixel-diorama）

> 平面的像素角色站進有縱深的佈景，燈光、遮擋和鏡頭讓這個小世界有了距離。
> 參照（只學語法）：像素精靈與立體場景結合的遊戲畫面、HD-2D 的空間組織、像素舞臺佈景。不照搬具體遊戲角色、地圖、介面、配樂或商標。

## 本質 / 不是什麼

- 本質：**像素畫的取捨與三維空間的光照同時成立**。角色仍是有限像素組成的平面精靈，地面、前景和遠景提供縱深，角色能被擋住，也能在腳下留下對應的影子。
- 不是：`pixel-game` 的純二維小畫布，也不是把普通低多邊形場景全屏打馬賽克。與 `tilt-shift-miniature` 相比，這裡最關鍵的是像素角色和立體環境之間可信的接觸。

## 辨識訊號：每支片子挑 2–3 個

| 訊號 | 長什麼樣 | 適合的主題 |
|---|---|---|
| 平面像素角色 | 少量像素簇概括身體，轉向時換對應檢視 | 角色、旅程、遊戲感 |
| 分層立體佈景 | 前景遮擋、中景路徑、遠景輪廓有真實距離 | 世界、探索、空間 |
| 腳底接觸影 | 小陰影跟腳的位置和地面高度變化 | 行走、落地、存在感 |
| 像素受光 | 角色亮暗隨場景燈光改變，輪廓仍清楚 | 時間、燈光、狀態 |
| 低解析度地表 | 紋理以有意組織的色塊表達石、木、水 | 環境、材料、場景 |
| 平面精靈遮擋 | 角色經過柱、樹和門時被正確擋住 | 深度、進入、路徑 |
| 選擇性景深 | 遠處變柔，當前角色保持像素結構 | 注意力、尺度、情緒 |
| 像素特效簇 | 火、水花或光點按塊變化，跟場景有位置關係 | 魔法、能量、反饋 |
| 前景擦鏡 | 近處屋簷或枝葉掠過，露出下一片空間 | 穿行、發現、轉場 |
| 步進姿態與平滑鏡頭 | 角色少幀動作，鏡頭緩慢連續移動 | 懷舊與空間感並存 |

規則：

- 每支挑 2–3 個，至少一個不在下面「最俗的版本」裡；訊號從主題裡選。
- 先定像素密度與場景尺度，再安排光效。角色、紋理與特效可以不同解析度，但差異要有依據，不能隨素材來源碰運氣。

## 這個風格最俗的版本

- 畫面：小勇者站在森林村莊中央，火把全開、螢火蟲滿天飛，強景深和泛光把一切照得夢幻。
- 聲音：懷舊冒險配樂加八位拾取音，每進一張地圖就響一段勝利旋律。
- brief 的 style 一欄寫明翻掉了哪幾條，或者為什麼保留經典版。現代車站、室內工坊或乾燥日光也能體現這種空間語言。

## 適配

- 用途：遊戲概念預告、故事向宣傳、品牌小世界、探索式片頭、氛圍循環。
- 內容：角色與環境的關係、旅途、發現、熟悉事物的像素化重述。
- 不適合：真實產品介面復現、密集數字展示，或需要自由近距離環繞精細人物的鏡頭。

## 技術路線

- **佈景與精靈**：Three.js 可組織地形、簡單建築和承載精靈的平面。紋理使用最近鄰取樣作為起點，角色朝向與相機關係需按鏡頭單獨設計。
- **受光與陰影**：可探索光照材質、簡化法線或分層明暗；影子按精靈的不透明輪廓處理，避免透明貼圖投出矩形陰影。固定機位也可用手工設計的接觸影近似。
- **像素動畫**：Canvas、Aseprite 匯出的授權圖集或自主繪製的幀圖都可用作素材；PixiJS 適合平面場景層。庫負責顯示，像素簇和姿態仍需設計。
- 圖集幀、位置、燈光和特效由時間獨立確定，隨機粒子固定種子。`--dpr` 與內部像素解析度分開考慮；`--subframes` 從低值試起，避免把步進動作抹成重影；`--grain` 通常關閉。

以上是候選方向，不繫結遊戲引擎或某種商業畫面方案。

## 材質與渲染

- 製作依據：先畫像素精靈與紋理，再把它們放進立體佈景。像素是有選擇的色塊，輪廓的臺階、暗部的簇和留空都應可辨。
- 角色腳底對齊地面接觸點，起伏地形同步調整高度與影子；不能讓人物像貼紙一樣懸在地表上方。
- 平面角色有可見角度限制。鏡頭繞行過大時，需要換方向幀、改變精靈朝向或重新構圖，避免突然變成一條薄邊。
- 近景像素保持清楚，遠處紋理要防閃爍；不要為了最近鄰銳利，把所有遠景都保留到無法穩定取樣的細節密度。
- 光照能改變色組亮度，但不能沖掉角色識別色。泛光主要給真實亮源與少量特效，正文和主體輪廓保持銳利。

## 配色

下面的色值是示例，看思路，不要原樣照抄。

- 日光石城：暗色 `#33485A` / 石面 `#B8B59A` / 植被 `#71845C` / 焦點 `#CC754C`。
- 暖燈工坊：環境 `#293642` / 木色 `#88634C` / 燈光 `#E0B56E` / 角色 `#97B6AE`。
- 冬日站臺：環境 `#CBD9D9` / 陰影 `#687E94` / 主體 `#4E626A` / 強調 `#B65848`。
- 推導：分別給環境、角色和亮源分配有限色組，靠明度讓角色從背景中分離。品牌色可以落在角色或目的地上，避免每種材料都共用一條萬能漸變。

## 字型

英文短標題可用 Pixelify Sans，輔助用 IBM Plex Sans；中文優先用思源黑體，自託管 OFL 字型。確需中文像素字時，使用授權清楚、覆蓋字表足夠的字型。像素字按合適倍數顯示，長字幕保持清晰，允許採用獨立的平面閱讀層。

## 運動

- 角色用少量關鍵姿態表達重心和方向，走路時足部接觸與位移匹配；不能只有整張貼圖上下彈動。
- 鏡頭可平滑，人物可步進，燈光可緩變；三者各有節奏，不把整片強行壓成同一種跳幀。
- 進出場依靠門、道路和遮擋，移動路徑有落腳點。特效跟動作發生的位置對應，不總從螢幕中央炸開。

## 畫面怎麼活

- 角色偶爾換一幀重心或衣襬，腳底位置基本不動；動作間留停頓。
- 窗光或火焰小幅變化，附近表面跟著受光，遠處不一起閃。
- 水面、蒸汽或枝葉用低密度循環，週期錯開，保留像素簇而非連續模糊噪聲。

## 鏡頭語法

| 鏡頭運動 | 表達什麼 | 適合哪類內容 |
|---|---|---|
| 小幅橫移，前景產生視差 | 場景有縱深 | 世界介紹、探索 |
| 跟隨角色穿過遮擋 | 身處其中 | 旅程、過程、發現 |
| 從地面稍稍抬高 | 當前地點與路徑關係 | 地圖、整體、結論 |
| 固定機位，光或角色改變 | 環境中的細微事件 | 情緒、循環、停留 |

## 聲音調色盤

第 1 檔可用 FM、撥絃、柔和鋪底與少量晶片音色，讓畫面保留像素記憶而不侷限於八位音效。需要鋼琴、絃樂或環境取樣時，用第 2 檔 Tone.js 配合授權素材。腳步按實際接觸點出現，遠近聲隨場景層級變化；口播時減掉頻繁的拾取提示。

律動與和聲（舉例，不止這些）：緩慢探索的分解和絃、明快的行進節奏，或夜間稀疏的電子氛圍。冒險、日常、工業場景可以用不同配器，不復制現有遊戲旋律。

## 原生手法

- 像素角色從暗處走入燈光，腳下陰影同時變化：適合角色與世界的初次建立（經典）。
- 前景樹幹或立柱擦過鏡頭，露出相連的新空間：適合旅程和連續轉場。
- 把平面地圖逐層立起，角色落到對應路徑上：適合進入世界和空間解釋。
- 景深從一個角色移到遠處目的地：適合目標、期待和敘事交接。
- 像素特效落地後變成場景中的實體細節：適合能量、建設和狀態變化。

## 變化空間

- 結構：跟一個角色經過幾處地點；同一場景隨時間改變；從環境細節拼出全貌。
- 開場：先聽見或看見區域性動作；前景遮擋被讓開；從二維圖案進入立體場景。
- 結尾：角色抵達後留一個安靜動作；抬高視角看到來路；燈光或路徑回到可循環狀態。

## 坑

- 全屏馬賽克取代像素設計：檢查角色輪廓和色塊是否在原始解析度下成立。
- 精靈投出矩形影子：陰影遵守透明輪廓，或改用有意設計的接觸影。
- 腳底滑動或懸空：對齊地面、位移和姿態週期。
- 鏡頭轉到精靈側面露餡：限制角度，或準備對應方向幀。
- 近景銳利但遠景不停閃：減少遠處紋理頻率，檢查最終影片中的運動取樣。
- 泛光與景深吞掉像素：保住當前主體邊緣，只軟化次要區域。
- 多來源素材像素大小不一致：先統一單位尺度和色組，再進入場景。
