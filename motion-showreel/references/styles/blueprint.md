# 工程藍圖（blueprint）

> 輪廓、尺寸線和剖面逐層出現，把一個物件怎樣組成、怎樣配合講清楚。
> 參照（只學語法）：曬圖工藝、工程製圖、建築圖紙與裝配說明。不照搬具體工程圖、產品結構和機構標識。

## 本質 / 不是什麼

- 本質：**用投影與製圖層級解釋結構**。實線說明可見邊，虛線提示隱藏部位，尺寸與引線把關係交代清楚；畫面首先是一張能讀懂的圖，再帶有曬圖的紙墨質感。
- 不是：`copperplate-engraving` 的白線版本，也不是 `hologram-hud` 的平面截圖。藍圖的排線表示剖面區域，通常不靠密集隨形排線塑造明暗；資訊依附圖紙座標，不懸浮在三維空間裡。

## 辨識訊號：每支片子挑 2–3 個

| 訊號 | 長什麼樣 | 適合的主題 |
|---|---|---|
| 多檢視對齊 | 正視、側視或俯視共用投影基準 | 產品、建築、組成 |
| 尺寸鏈 | 尺寸線與延長線分層排在物體外 | 比例、規格、精確關係 |
| 線型分工 | 可見邊、隱藏邊、中心線有不同線型 | 結構、內部關係 |
| 剖切視窗 | 區域性外殼讓出位置，露出帶排線的截面 | 原理、材料、內部 |
| 爆炸裝配 | 零件沿裝配軸分開，彼此仍對得上 | 工藝、模組、協作 |
| 區域性詳圖 | 一個節點被放大，旁邊標出對應位置 | 精密連線、重點功能 |
| 圖框與標題欄 | 圖名、版本、比例說明有固定位置 | 方案、迭代、檔案 |
| 修訂雲線 | 改動區域被圈出，舊版與新版有對應 | 更新、對比、糾錯 |
| 構造輔助線 | 幾何基準先出現，成圖後部分退去 | 從想法到結構、方法 |
| 曬圖邊緣 | 藍色紙面有很輕的曝光差異與摺痕 | 製作、歷史、實體圖紙 |

規則：

- 每支挑 2–3 個，至少一個不在下面「最俗的版本」裡；訊號從主題裡選。
- 數字、比例、零件關係必須有依據。沒有工程資料時明確標「示意」，可以省掉數值，不能用隨機尺寸裝出專業感。

## 這個風格最俗的版本

- 畫面：藍底網格、白線從左掃到右，正中一個機械物件，四周密密麻麻的尺寸和無意義編號。
- 聲音：畫線必配電流聲，數字跳動必配滴聲，完成時來一下金屬撞擊。
- brief 的 style 一欄寫明翻掉了哪幾條，或者為什麼保留經典版。可以用無網格的區域性詳圖、修訂對比或圖紙摺疊建立重點。

## 適配

- 用途：產品原理講解、結構展示、方案比較、工藝宣傳、技術片頭。
- 內容：建築、工程、模組化服務，以及能誠實表達為結構關係的概念。
- 不適合：需要照片級材質判斷的產品片、情緒主導的生活片，或把未知內部結構包裝成事實的講解。

## 技術路線

- **平面製圖**：SVG、Canvas 都可；DOM 可承載獨立的標題與說明。路徑求交、剖面裁切可考慮 Paper.js，線型與文字層級按本片圖紙設計。
- **多檢視與裝配**：若有授權模型，可探索 Three.js 正交相機、邊線與剖切表現。多檢視儘量來自同一個幾何物件，避免手畫三張彼此矛盾的圖。
- **紙面質感**：用區域性紋理或輕量著色器表達曬圖密度，PixiJS 可輔助遮罩；資訊層先保持清晰，再加紙紋。
- 任意時間獨立恢復零件位置、引線端點與顯現狀態；紙紋固定種子。`--dpr` 以虛線和小字可讀為準，`--subframes` 從輕，`--grain` 不得破壞虛實線差別。

以上是可選路線；不預設 CAD 引擎、圖紙標準或具體繪圖程式碼，涉及專業標準時按資料採用。

## 材質與渲染

- 工藝依據：傳統藍曬複製通過曝光與水洗留下藍色底和淺色線。印好的圖紙是平面材料，線本身不發光。
- 可見輪廓最醒目，尺寸與輔助線次之，網格最弱。線寬有可見差別，不能靠一堆近似白線讓觀眾猜層級。
- 剖面排線在同一材料區域內方向和間距穩定，邊界裁切乾淨；相鄰零件可用不同方向區分，不把它當立體明暗。
- 尺寸文字留線上的上方或斷口內，引線終點準確貼住物件。鏡頭移動時，文字與圖紙一起移動，不在螢幕上漂浮。
- 摺痕和曝光差只輕微影響底紙；前景主體也遵守制圖線型，不在藍圖中間貼一張寫實渲染圖。

## 配色

下面的色值是示例，看思路，不要原樣照抄。

- 深藍曬圖：底 `#153C68` / 主線 `#E5F0EB` / 修訂 `#EDBB72`。
- 淺底工作圖：底 `#E8EEEA` / 主線 `#244B66` / 修訂 `#B34E40`。
- 暗青方案圖：底 `#163F46` / 主線 `#D7E9DD` / 強調 `#E5C06D`。
- 推導：底色從品牌色裡取穩定的暗色或低飽和淺色，線與底保持反差。強調色只表示當前剖切、選中或修訂的一類資訊，並在全片保持同義。

## 字型

英文和數值可選 IBM Plex Mono、Roboto Mono，中文用思源黑體，自託管 OFL 字型。數字保持等寬，單位與數值留出間隔。標題比標註大一檔，標註先按最終手機尺寸定字號，再決定一鏡能容納多少條尺寸。

## 運動

- 圖形顯現按理解順序組織：可以先給整體輪廓，再揭示某一連線；不必每次從網格開始。
- 爆炸裝配沿真實或明確的示意軸移動，起止位置能對合。零件運動平穩，幾乎不回彈，避免變成玩具散落。
- 尺寸線在對應結構穩定後出現，更新結構時同步更新標註。離場可換檢視、收起剖切或翻到下一版圖紙。

## 畫面怎麼活

- 圖紙閱讀時以靜為主，已完成的尺寸與輪廓不閃爍。
- 講機械關係時，一個機構緩慢走完小幅工作行程，中心線與連線點保持一致。
- 修訂場景可讓剖切面緩慢移動，或讓區域性詳圖的觀察範圍沿物件平移；每次只讓一個重點變化。

## 鏡頭語法

| 鏡頭運動 | 表達什麼 | 適合哪類內容 |
|---|---|---|
| 垂直圖紙的固定機位 | 客觀、方便比較 | 尺寸、結構、版本 |
| 從全圖推到一個節點 | 解釋關鍵連線 | 產品細節、原理 |
| 沿投影線從一個檢視移到另一個 | 同一物件的不同觀察面 | 建築、多檢視 |
| 固定尺度，圖層依次展開 | 各層如何配合 | 裝配、模組、剖面 |

## 聲音調色盤

第 1 檔可用短促的木質敲擊、低音脈衝和少量乾燥噪聲，分別對應定位、移動和圖層切換。需要鉛筆、描圖紙、量具擬音時，用第 2 檔 Tone.js 配合授權取樣。只給有意義的落位配音，尺寸文字出現不必逐字滴響；有口播時壓低細碎高頻。

律動與和聲（舉例，不止這些）：均勻而稀疏的脈衝、帶停頓的機械節奏，或溫和的室內樂分句。技術內容可以有溫度，不必統一成警報式科幻音軌。

## 原生手法

- 輪廓完成後，尺寸與引線分組補齊：適合結構建立和片頭（經典）。
- 剖切線穿過外殼，露出截面，再轉成區域性詳圖：適合內部原理。
- 同一零件在正視與側視間沿投影基準對應：適合解釋空間關係。
- 修訂雲線包住改動，舊線退去、新線就位：適合版本升級和方案對比。
- 爆炸圖沿裝配軸收攏，同時讓標註歸入標題欄：適合從組成走到整體結論。

## 變化空間

- 結構：圍繞一個關鍵節點深入；多檢視逐個回答問題；兩張方案圖並列比較。
- 開場：先出現一條需要解釋的剖切線；從區域性錯配開始；展示完整圖紙後拿掉一層。
- 結尾：保留可讀的定稿；只留最關鍵的結構關係；圖紙收起，轉到下一章的區域性。

## 坑

- 隨機編號和尺寸看似專業卻互相矛盾：依據資料填寫，未知項刪去或標示意。
- 三個檢視形狀對不上：共用幾何依據，至少核對對應長度與孔位。
- 引線端點隨動畫脫離物件：端點與物件位置一起求取。
- 所有線一樣亮：先拉開輪廓、標註、輔助線的層級。
- 剖面排線穿過空腔：按實體區域裁切，空腔保持空白。
- 鏡頭縮小後小字無法讀：減少同時出現的標註，另開詳圖，不只提高解析度。
- 藍底加發光遮住曬圖質感：把光暈去掉，先看圖紙是否仍成立。
